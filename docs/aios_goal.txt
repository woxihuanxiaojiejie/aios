# AIOS 系统最终需要完成什么

AIOS 不是一个“展示股票信息的网页”，也不是单纯让大模型给出买卖建议。它最终需要成为一套能够持续运行的**自动投研、决策、验证和学习系统**。

核心闭环是：

> **真实信息进入 → 提出可验证假设 → 多 Skill 分析 → 两阶段讨论 → 生成交易决策 → 模拟执行 → 到期结算 → 复盘责任 → 调整权重 → 下一轮继续验证**

---

## 一、真实数据与证据系统

AIOS 首先必须接入真实数据，禁止依靠大模型凭空分析。

需要覆盖：

* A 股实时行情和历史行情
* 美股实时行情和历史行情
* 大盘、行业、概念板块数据
* 个股公告
* 新闻
* 政策文件
* 财报及基本面数据
* 市场情绪和资金流向数据
* 后续用于结算的真实价格数据

所有外部信息进入系统后，都必须转换成统一的 `Evidence`。

每条 Evidence 至少要保存：

* 来源
* 原始标题和正文
* 发布时间
* 抓取时间
* 涉及股票、板块和市场
* 信息类型
* 原始链接
* 内容指纹
* 可信度
* 时效性
* 是否已经用于研究
* 原始数据和解析失败信息

核心原则：

* 政策权重高于普通新闻。
* 公告优先于媒体转述。
* 不能只有摘要，必须保留原文或原始响应。
* 相同信息需要去重。
* 抓取失败不能静默丢弃。
* 所有数据必须持久化，服务重启后不能丢失。

---

## 二、研究对象与观察池

用户需要能够维护自己的研究范围，包括：

* 自选股 Watchlist
* 关注板块
* 关注主题
* 重点政策方向
* A 股和美股市场范围
* 暂时停用但保留的研究对象

系统应当定期扫描这些对象的新信息，而不是每次都由用户手动发起。

Watchlist 需要支持：

* 新增股票
* 删除股票
* 启用或停用
* 查看股票对应的新证据
* 查看历史研究记录
* 查看当前有效假设
* 查看尚未结算的交易决策

当前内存版 Watchlist 只是临时状态，最终必须接入 PostgreSQL。

---

## 三、自动假设生成

新闻、政策、公告和市场变化进入系统后，AIOS 不能只做摘要，而要提出可以验证的市场假设。

例如，一条假设应当明确：

* 哪个事件触发了假设
* 影响哪只股票或哪个板块
* 预期上涨、下跌还是不确定
* 预计影响持续多长时间
* 作用机制是什么
* 哪些条件支持该假设
* 哪些条件会使假设失效
* 如何通过真实市场数据验证

假设必须是 Evidence-first：

> 先有证据，再有假设，不能由模型随意编造。

但系统不能因为“没有特别强的新观点”就完全停止研究。它可以从现有证据中提出低置信度假设，明确标记其不确定性，再通过市场验证，而不是假装存在确定结论。

假设周期主要包括：

* 1 日
* 3 日
* 7 日

后续可以扩展，但第一阶段不需要无限增加周期。

---

## 四、单 Agent + 多 Skill 分析

AIOS 当前确定采用：

> **一个研究 Agent，按需要调用多个 Skill**

不再默认让大量独立 Agent 重复读取相同材料，以减少 Token 消耗和系统复杂度。

第一批核心 Skill：

1. `technical_trend`

   * 趋势
   * 均线
   * 成交量
   * 支撑压力
   * 强弱结构
   * 技术形态

2. `sector_strength`

   * 板块强弱
   * 板块内部扩散
   * 龙头地位
   * 资金持续性
   * 个股相对板块强弱

3. `policy_impact`

   * 政策级别
   * 影响链条
   * 受益和受损方向
   * 政策时效
   * 市场是否已经交易预期

4. `announcement_risk`

   * 公司公告
   * 财务风险
   * 减持
   * 解禁
   * 监管
   * 诉讼
   * 业绩变化
   * 重大事项

5. `market_sentiment`

   * 市场风险偏好
   * 涨跌停结构
   * 赚钱效应
   * 情绪周期
   * 成交活跃程度
   * 主线和防御方向切换

Skill 需要支持：

* 根据证据类型自动选择
* 根据当前市场环境选择
* 调用历史上有效的 Skill
* 随时启用、停用或替换
* 单个 Skill 失败不影响其他 Skill
* 输出严格结构化
* 每个结论必须引用 Evidence
* 解析失败时只允许有限修复重试
* 保存模型原始输出和错误信息

---

## 五、两阶段研究讨论

虽然采用单 Agent + 多 Skill，但仍然要保留原先设计的“两阶段讨论思想”。

### 第一阶段：独立盲评

每个被调用的 Skill 独立分析：

* 不查看其他 Skill 的结论
* 不迎合已有观点
* 独立给出方向、理由、置信度和风险
* 必须引用证据

这一阶段用于保留不同分析角度，避免所有结论互相污染。

### 第二阶段：交叉讨论

第一阶段完成后，研究 Agent 汇总全部报告并进行讨论：

* 找出一致观点
* 找出冲突观点
* 判断冲突来自数据差异还是解释差异
* 对证据强弱进行比较
* 指出谁可能高估或低估了影响
* 明确最关键的不确定因素
* 形成最终研究结论

系统不能只输出“多数 Skill 看多，所以看多”。必须保留少数反对意见及其证据。

---

## 六、策略因子与动态权重

每个 Skill、证据类型和策略因子都需要有权重。

权重不是大模型随意改写的数字，而是系统中的正式状态。

需要管理的权重至少包括：

* Skill 权重
* 政策证据权重
* 公告证据权重
* 新闻证据权重
* 技术趋势权重
* 板块强度权重
* 市场情绪权重
* 不同市场环境下的条件权重
* 不同预测周期下的权重

权重不能只有一个永久值，而要包含：

* 当前值
* 初始值
* 最小值和最大值
* 适用市场状态
* 适用预测周期
* 修改原因
* 修改前后数值
* 对应的历史决策和验证结果
* 修改者
* 生效时间
* 是否可以回滚

### 权重调整原则

模型不能直接永久修改正式权重。

正确流程是：

1. 结算发现某个 Skill 持续有效或持续失效。
2. 系统生成 `Learning Proposal`。
3. Proposal 说明建议调整哪个权重、调整多少、依据是什么。
4. 通过规则或用户批准。
5. 正式应用修改。
6. 保留审计记录。
7. 效果变差时可以回滚。

Skill 也可以主动申请降低自己的权重，但仍然需要经过 Proposal 流程。

---

## 七、决策引擎

研究完成后，系统需要生成正式的 `Decision`，而不是一段普通文本。

一个决策至少应包含：

* 研究对象
* 看多、看空或不交易
* 决策置信度
* 预测周期
* 目标区间
* 入场条件
* 止损或失效条件
* 风险因素
* 仓位建议
* 关键证据
* 支持该决策的 Skill
* 反对意见
* 当前市场状态
* 决策生成时间
* 计划结算时间

必须支持：

* `long`
* `short` 或规避
* `no_trade`

其中 `no_trade` 是正式决策，不是系统失败。

AIOS 不能为了每天都有操作而强行给出买卖信号。

---

## 八、风险审查

在 Decision 生效前，需要经过独立的风险审查。

风险审查关注：

* 证据是否过期
* 是否存在重大公告风险
* 是否处于异常波动期
* 是否已经高位兑现
* 是否存在流动性问题
* 板块强但个股弱，或个股强但板块弱
* 决策是否过度依赖单条证据
* 多个 Skill 是否实际上引用了同一来源
* 模型置信度是否与证据强度匹配
* 是否应该改为 `no_trade`

风险审查可以：

* 通过
* 降低置信度
* 缩小仓位
* 修改条件
* 否决为 `no_trade`

---

## 九、交易计划与模拟执行

系统不能只停留在研究报告，还要生成可验证的交易计划。

第一阶段先做模拟执行，不直接连接真实券商下单。

模拟执行需要保存：

* 计划价格
* 触发时间
* 实际触发价格
* 模拟买入或卖出
* 模拟仓位
* 手续费和滑点
* 是否未触发
* 未触发原因
* 持仓期间价格变化
* 风险条件是否触发
* 最终退出价格和时间

这样才能区分：

* 方向判断正确
* 方向正确但入场条件错误
* 策略正确但执行失败
* 靠偶然波动获利
* 真正稳定有效

---

## 十、自动结算

每个 1 日、3 日、7 日决策到期后，系统必须自动获取真实行情并结算。

结算结果至少包括：

* 起始价格
* 结束价格
* 期间最高价
* 期间最低价
* 收益率
* 最大有利波动
* 最大不利波动
* 是否达到目标
* 是否触发止损
* 方向是否正确
* 实际执行收益
* 是否属于偶然命中
* 是否违反原定条件

结算必须使用真实行情，不能由大模型自行判断“这次预测成功”。

---

## 十一、三轴评估

AIOS 不能只看最终赚没赚钱，而要至少从三个维度评估。

### 1. 方向准确性

判断上涨、下跌或不交易是否正确。

### 2. 收益质量

判断是否真正产生可执行收益，而不是盘中偶然触碰目标。

### 3. 风险与过程质量

判断：

* 回撤是否过大
* 是否违反止损
* 是否过度承担风险
* 入场条件是否合理
* 决策过程是否符合证据

用户已经明确：

> 准确率低但偶尔收益很高，不能直接认为策略优秀，因为可能只是凑巧。

因此系统要优先识别稳定认知，而不是奖励偶然暴利。

---

## 十二、责任归因与复盘

每次决策结算后，需要生成 Review。

Review 要回答：

* 原假设是否成立
* 哪些 Evidence 最关键
* 哪些 Evidence 被误读
* 哪个 Skill 判断正确
* 哪个 Skill 判断错误
* 错误来自数据、逻辑、时机还是执行
* 市场环境是否发生变化
* 原有因果是否已经失效
* 这是一次错误，还是原策略适用环境已经结束
* 是否需要调整权重
* 是否需要停用某个假设
* 是否需要新增或修改 Skill

系统需要允许得出：

> “之前的判断在当时有效，但当前风口已经改变。”

不能把所有失效都简单归结为“以前完全错了”。

---

## 十三、学习系统

Review 之后，系统生成 Learning Proposal。

第一阶段可支持：

* 调高 Skill 权重
* 调低 Skill 权重
* 调整证据类型权重
* 将某个假设标记为失效
* 将某个策略设为休眠
* 在特定市场环境重新启用旧策略
* 修改 Skill 的适用条件
* 建议增加新 Skill
* 建议修改提示词或分析规则

每个学习建议必须有：

* 建议内容
* 数据依据
* 关联决策
* 样本数量
* 成功率
* 收益表现
* 风险表现
* 适用范围
* 可能副作用
* 回滚条件

不能因为一次预测失败就大幅调整权重，必须防止过拟合。

---

## 十四、历史记忆与策略复用

AIOS 需要记住历史，但不能简单把所有旧内容塞给模型。

需要保存并检索：

* 历史 Evidence
* 历史 Hypothesis
* 历史 Skill 报告
* 历史 Decision
* Outcome
* Evaluation
* Review
* Learning Proposal
* 权重修改历史
* 市场状态
* 策略适用条件

当市场环境与历史阶段相似时，系统应能够：

* 找到过去使用过的 Skill
* 找到相似假设
* 查看过去成功和失败记录
* 恢复处于休眠状态的策略
* 说明为什么本次复用

历史策略不是删除，而可以标记为：

* active
* inactive
* invalid
* dormant
* candidate_for_reactivation

---

## 十五、市场状态识别

同一个 Skill 在不同市场环境下可能效果完全不同，因此 AIOS 需要识别市场状态。

第一阶段至少包括：

* 趋势上涨
* 趋势下跌
* 震荡
* 高波动
* 低波动
* 风险偏好
* 防御切换
* 主题集中
* 快速轮动
* 缩量市场
* 放量市场

市场状态会影响：

* Skill 选择
* Skill 权重
* 交易周期
* 仓位
* 是否允许交易
* 历史策略召回

---

## 十六、数据库持久化

核心对象必须进入 PostgreSQL，不能依赖 Python 内存变量。

至少需要持久化：

* Watchlist
* Evidence
* Research Session
* Hypothesis
* Skill Report
* Debate / Discussion
* Proposal
* Risk Review
* Decision
* Trade Plan
* Simulated Execution
* Outcome
* Evaluation
* Review
* Learning Proposal
* Skill 配置
* 权重
* 权重变更记录
* 市场状态
* Provider 调用记录
* 原始模型输出
* 系统错误和任务状态

数据库变更统一通过 Alembic 管理。

需要验证：

> API 重启、Worker 重启、Docker 重启后，研究数据仍然存在。

---

## 十七、自动任务调度

系统最终需要由调度器自动运行，而不是只能点击按钮。

定时任务至少包括：

* 抓取新 Evidence
* 更新行情
* 扫描 Watchlist
* 生成新假设
* 启动研究
* 到期结算
* 生成 Review
* 生成 Learning Proposal
* 检查失败任务
* 重试可恢复任务

同时必须防止：

* 同一证据重复处理
* 同一研究重复执行
* 同一决策重复结算
* Worker 重启导致任务丢失
* 重试导致重复写入

---

## 十八、模型和 Provider 管理

主要模型：

* DeepSeek 为默认模型
* GPT 可作为备用或特定任务模型

需要实现：

* Provider 配置检查
* 模型能力兼容检查
* JSON structured output
* 超时
* 重试
* 限流
* 失败隔离
* 原始响应保存
* Token 和费用统计
* 模型切换
* 单个 Skill 指定模型
* 外部真实模型 Smoke Test

模型失败不能让整个研究 Session 崩溃。

---

## 十九、API 与前端

前端只是操作和观察 AIOS 的入口，不是系统主体。

页面应当保持简单，重点包括：

### Research

* Watchlist
* 发起研究
* 当前研究状态
* Evidence
* Hypothesis
* Skill 报告
* 第二阶段讨论
* 最终 Decision

### Events / Evidence

* 新闻
* 政策
* 公告
* 数据来源
* 处理状态
* 关联股票和研究

### Experiments

* 历史假设
* 验证周期
* 结果
* 成功和失败原因

### Trade Plans

* 当前计划
* 模拟执行
* 持仓状态
* 待结算任务
* 已结算结果

### AI Center

* Skill 状态
* 权重
* Provider
* 模型调用
* Learning Proposal
* 错误记录

页面不需要做成复杂交易终端，行情图表可继续使用同花顺等成熟工具。

---

## 二十、工程质量与可运行性

系统必须做到：

* 前后端默认端口统一
* Docker Compose 可以完整启动
* 不连接旧服务
* 环境变量明确
* 健康检查不仅检查进程，还检查关键路由
* PostgreSQL、Redis、Worker、Scheduler 状态可见
* 完整测试
* 类型检查
* 代码格式检查
* 数据库迁移检查
* 外部模型 Smoke Test
* 关键业务端到端测试
* 所有变更可通过 Git 审计

关键 Smoke 至少验证：

1. 添加 Watchlist 股票。
2. 抓取真实 Evidence。
3. Evidence 生成 Hypothesis。
4. 自动选择多个 Skill。
5. 第一阶段独立报告。
6. 第二阶段讨论。
7. 生成 Risk Review 和 Decision。
8. 生成模拟 Trade Plan。
9. 到期获取真实行情。
10. 生成 Outcome、Evaluation、Review。
11. 生成 Learning Proposal。
12. 重启服务后上述数据仍存在。

---

# AIOS 最终验收标准

AIOS 达到“可以正常使用”，不能只看接口数量或测试通过数，而要验证下面这条真实闭环：

> 用户把股票加入 Watchlist 后，系统能够自动抓取真实新闻、政策、公告和行情；基于 Evidence 提出假设；调用合适的 Skill 独立分析；完成第二阶段讨论；生成包含入场、退出和失效条件的决策；进行模拟执行；在 1、3、7 日后使用真实行情自动结算；分析谁判断正确、谁判断错误；提出权重调整建议；并在后续研究中真正使用新的权重。

这条链路完整运行，并且数据在服务重启后仍然存在，才算 AIOS 核心系统完成。

当前 BRAIN-001～005 主要完成的是**大脑研究链路和闭环骨架**。接下来最重要的不是继续增加新概念，而是把现有链路接入：

> **PostgreSQL 持久化 → 自动调度 → 真实数据 → 模拟执行 → 自动结算 → 权重真正生效 → 端到端验收。**
